\section{Conclusion}
This project built a parameterized output-stationary systolic array for fixed-point matrix multiplication in synthesizable Verilog-2005, and took it from a single $N \times N$ product in Phase~1 to products of any size in Phase~2. Two small changes outside the array made this possible: a run-time inner length, which sets how long the skew buffers feed operands and how many steps the controller runs, and an accumulate start that skips the clear, so the partial sums of a tile stay in their PEs from one chunk of the inner dimension to the next. The array and its PEs did not change. Every run meets the written timing contract of $k_{\mathrm{len}} + 2N$ busy cycles. A sequential baseline with the same interface lets the same testbenches measure the benefit of the array: 5.3 times fewer busy cycles for $k_{\mathrm{len}} = 4$, rising to 10.7 for $k_{\mathrm{len}} = 16$, because the fill and drain of the wavefront are paid once per run. Synthesis for an ECP5 FPGA with open-source tools gives the resources and clock frequency of both designs (Section~V).

The results also show the limits of the design. The host writes and reads one element per cycle, so loading a run's operands takes $N k_{\mathrm{len}}$ cycles, more than the run itself, and the end-to-end speed-up of an $8 \times 8 \times 8$ product is 2.7 against 8.0 for the array alone. The wavefront's $2N - 2$ cycles of fill and drain are paid on every run, so a PE is busy for at most 72.7\,\% of the compute steps, and the edge tiles of a product whose size is not a multiple of $N$ spend as long on zero padding as on useful work. Results stay at 32 bits, with no rounding or saturation back to 8 bits. The design was evaluated in simulation and by static timing analysis only, since no FPGA board was available. These limits set the next steps: double-buffered or wider operand ports that overlap loading with computing, rounding and saturation of the results, and running the design on an FPGA board.
